# agent-loop-observability Specification (Delta)

## ADDED Requirements

### Requirement: 每轮来源事实可查

系统 SHALL 为每次生成记录足以判定"这一轮由谁、以何种采样参数产生"的日志，且无需依赖数据库反查：

- 每次 LLM 调用的采样温度（含**实际取值来源**：显式传参 / 沿用构造默认）与是否绑定 KB 的档位；
- 生效智能体及其来源（沿用绑定 / 首次绑定 / 请求不一致被忽略 / 未注册降级 / 未绑定）；
- 人设是否实际生效（是否取自智能体预设）。

#### Scenario: 温度可从日志直接读出

- **WHEN** 排查某轮生成使用的采样温度
- **THEN** 该轮每次 LLM 调用的日志行含采样温度、取值来源（显式传参 / 沿用默认）与 KB 档位，且日志值与实际传给模型的值为同一来源

#### Scenario: 生效智能体与来源可读

- **WHEN** 排查某轮生效的智能体
- **THEN** 日志含请求值、会话绑定值、生效值与其来源（绑定 / 新增绑定 / 不一致忽略 / 未注册降级 / 未绑定）

#### Scenario: 人设生效与否可读

- **WHEN** 某轮绑定了智能体预设
- **THEN** 日志记录人设是否生效，从而可区分"人设已替换基础段"与"未选智能体沿用默认人设"

#### Scenario: 普通文本轮不产生来源噪声

- **WHEN** 某轮既未绑定智能体、也无请求值
- **THEN** 不产出 `agent resolved` 日志行

### Requirement: 技能加载与分派可查

系统 SHALL 记录本轮技能相关事实：**命令形态**的分派结果（命中已注册 / 形如命令但未注册）、技能执行形态（inline / fork）、技能正文成功注入（区分"用户命令触发"与"预设预加载"）及注入体量。**非命令（普通文本）轮 SHALL NOT 记录分派日志**——事件级别由 `EventSpec` 固定、调用点不能逐次降级，故以"不记"控制噪声。失败跳过仍按既有告警记录。

#### Scenario: 命令形态分派可读

- **WHEN** 某轮输入形如命令（命中已注册 / 形如命令但未注册）
- **THEN** 日志含解析结果、技能名、执行形态与直接执行目标；普通文本轮不产出该分派日志

#### Scenario: 注入来源可区分

- **WHEN** 某轮向会话注入了技能正文
- **THEN** 日志区分该注入来自用户命令还是预设首轮预加载，并记录体量（字符数）

#### Scenario: prompt 组成可读

- **WHEN** 排查某轮的 system prompt 构成
- **THEN** 日志含人设来源（预设 / 基础）、KB 是否绑定、纪律段与委派段是否注入

#### Scenario: 消息构成可读

- **WHEN** 排查某轮送入模型的消息条数
- **THEN** 日志分别给出生效 system 消息数、注入消息数与历史消息数，且三者之和与实发条数一致
