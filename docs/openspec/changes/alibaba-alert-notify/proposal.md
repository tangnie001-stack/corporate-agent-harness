## Why

线上出故障时，阿里云的告警目前只能落到企微群/短信，是一行文本 —— 想看原因还得人工再去翻日志。本项目已经有 Agent 与检索能力，希望让告警直接走进来：**收到告警 → Agent 自动分析 → 结论推回值班群**，省掉"看到报警再手动排查"这一跳。

## What Changes

- **新增告警接收接口**（HTTP POST）：供阿里云 ARMS「通用 Webhook」通知对象调用。
- **端点契约：收包即返**（校验与去重通过后立刻返回，不等待分析）—— ARMS Webhook **硬超时 5 秒**；分析与推送在后台任务里跑。
- **鉴权**：用**请求头**承载固定 token（**独立配置键** `ALERT_WEBHOOK_TOKEN`；ARMS Webhook 支持自定义 Header），失败返回 404（不返回 401/403，不暴露端点存在）。token 不进 URL，避免被访问日志记录。
- **配置可选**：未配置 token 时端点恒 404，不阻断应用启动。
- **入口去重**：**逐条**取 `alerts[].fingerprint`，配可配置时间窗；窗口内的重复请求丢弃。
- **载荷契约**：ARMS 侧**必须**按本项目规定的自定义 body 模板推送（默认模板缺 `alarmId`/`fingerprint`），字段清单与解析实现**一一对应**，模板正文记录于 runbook。
- **在独立会话里跑一轮 Agent**：会话 key 由**报警自带标识**派生，与企微群/单聊问答历史隔离；使用**固定 `user_id`**；不挂知识库、不绑定智能体预设；**不接受澄清追问**；整轮有**超时**。
- **主动推送分两段**：入口去重之后立刻推一条**受理占位**，分析完成后再推**结论**（两条独立消息 —— 主动推送无入站 `req_id`，因此无流式、不可更新）。
- **失败即兜底**：分析失败 / 超时 / **结论为空** / **并发繁忙** 时，把阿里云原始内容转发到群（带前缀标记、限长、不写入报警会话历史）。
- **目标群单目标先写死**：配置就一个 `{bot_key, chatid}`（机器人**复用现有 `dev`**）；订阅式与多群**留待后续**（多群可把 token 解释为路由键，**不用改 URL 形状**）。
- **会话可见性**：报警会话使用固定 `user_id`，普通用户的会话列表天然看不到（不额外做隐藏）。
- **配置化**：告警 token、目标群、去重时间窗、整轮超时、固定 `user_id`、占位与兜底文案，统一进 `src/config/`。

## Capabilities

### New Capabilities

- `alert-notify`: 阿里云告警接入全链路 —— 接收与鉴权、去重、目标路由、独立会话的 Agent 分析、两段式主动推送、失败兜底转发。

### Modified Capabilities

- `wecom-channel`: 新增「**主动推送消息到指定会话**」能力（现有 spec 仅覆盖"对入站帧回复"）。涉及会话寻址（群 `chatid` / 单聊 `userid`）、一次性发送语义、发送失败处理与就绪判据。

## Impact

- **代码**：新增 API 路由（`src/api/`）、服务层编排、企微通道新增主动发送出口（`src/channels/wecom/`）、配置项（`src/config/`）、渠道标识登记（`docs/agents/logging-rules.md`）。
- **依赖**：aibot SDK 的 `client.send_message(chatid, body)` —— **已 spike 通过**（`wecom-sdk-facts.md` E12/E12b）：可向群主动发送、**无流式**、错误码 `93006`/`40008`、chatid 为**群维度且未交互也能发**。因此"两段式"是终态形态。**残留风险**：生产机 + 目标群上的端到端效果未验。
- **阿里云侧**：ARMS 通知策略 + 「通用 Webhook」通知对象。该通知对象支持**自定义 Header（Header+Param ≤6 个）**与**自定义 body 模板（Go Template，≤500 字符）** —— 前者用于传 token；后者**为必需**（默认模板不含 `alarmId`/`fingerprint`），其正文由本项目规定并记录于 runbook，即**本能力的载荷解析契约**。
- **数据**：报警会话写入 `sessions` / `conversation_history`（每个报警事件一行会话）；`user_id` 为全零 UUID。
- **不改动**：现有站点问答链路与企微「@ 机器人」问答链路保持不变。
- **待实测校准**：`alarmId` 在同一告警重复通知时是否恒定；群聊入站帧的 `chatid` 实际形态（用于首次确定写死的群 id）；ARMS 实际推送载荷字段。
