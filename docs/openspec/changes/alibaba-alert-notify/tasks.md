## 1. Spike：验证主动推送（前置）

- [ ] 1.1 写一次性探针脚本，用现有某台机器人凭证调 SDK `send_message(chatid, body)`，验证能否向**群**主动发出消息
- [ ] 1.2 验证目标限制：未经交互的群/用户能否收到；记录失败错误码
- [ ] 1.3 验证节奏与**频率上限**（两段式使消息数翻倍），记录连发表现
- [ ] 1.4 在目标群 @ 一次机器人，从 `sessions.title`（`[企微·<bot_key>] 群聊 <chatid>`）读出 `chatid` 明文并登记（注意 `title` 仅首次落库生效）
- [ ] 1.5 结论（可用性、失败码、频率上限）回写 `docs/agents/wecom-sdk-facts.md`

## 2. 配置

- [ ] 2.1 `src/config/` 新增告警配置：接收 token、目标群（**单行 JSON**，含 `bot_key` + `chatid`）、去重时间窗、整轮超时、固定 `user_id`（全零 UUID）、占位与兜底文案、兜底长度上限、query 模板
- [ ] 2.2 启动期校验（对齐 `src/config/wecom_bots.py` 的做法）：单行 JSON、必填非空、非法即 fail-fast 且不回显敏感值；**token 为空视为"未配置"**，不阻断启动
- [ ] 2.3 同步 `.env.template` 与 `.env.example`（**两个文件都要改**）
- [ ] 2.4 渠道值 `ALERT` 进 `src/config/`（常量），文案类承载占位与兜底文本

## 3. 通道层：主动推送（wecom-channel）

- [ ] 3.1 新增对外发送出口（封装 SDK `send_message`），入参 = `bot_key` + 目标会话 + 内容；docstring 写明**一次性发送、无流式、不可更新**
- [ ] 3.2 目标未配置 / 机器人不存在 / 连接未就绪 → 记 warning 并返回失败，**不回落到默认会话**
- [ ] 3.3 发送失败记含**目标会话标识与错误码**的日志，值按日志规约编码
- [ ] 3.4 单测：成功 / 目标未配置 / 发送失败 三条路径

## 4. 告警接收端点

- [ ] 4.1 新增 `POST` 端点；token **从请求头读取**，用 `hmac.compare_digest` 做常数时间比较
- [ ] 4.2 token 不匹配或未配置 → 返回 **404**；端点不依赖登录态
- [ ] 4.3 **校验 + 去重通过后立即返回成功应答**（须在上游 5 秒硬超时内），分析与推送放进后台任务；应答**不表达**分析结果
- [ ] 4.4 载荷解析：`alarmId` / **逐条** `alerts[].fingerprint` / `commonLabels.alertname` / `level` / `alerts[].annotations.message`；缺必填或 JSON 非法 → 记 warning + 可识别错误响应（不得抛未处理异常）
- [ ] 4.5 单测：鉴权三态（正确/错误/未配置）；立即应答（模拟慢分析不拖住响应）；载荷正常 / 多条 alert / 缺字段 / 非法

## 6. 报警分析编排

- [ ] 6.1 派生报警会话标识（`scope=alert`，与群聊/单聊问答会话隔离），标识来源 = 报警自带标识
- [ ] 6.2 装配 `start_turn`：固定 `user_id`（全零 UUID）、`kb_id=""`、`agent=""`，title 取 `[企微·<bot_key>] 报警 <alertname>`；**query 由 `src/config/` 的模板构造**
- [ ] 6.3 入口设置渠道上下文（`ALERT`）
- [ ] 6.4 报警轮**不注册 `ask_user`**：给 `start_turn` 开"按轮次覆盖工具集"的口子（`build_graph(tools=...)` 已支持覆盖，缺透传）；注意 `CLARIFICATION_ENABLED` 是**死配置**，别当成开关
- [ ] 6.5 整轮超时：用 deadline 包住事件消费，超时即取消该轮（阈值取 `src/config/`）
- [ ] 6.6 去重通过后**立刻推受理占位**（文案取 config）；失败只记 warning，不阻断分析、不落历史
- [ ] 6.7 正常完成 → 推**结论**到目标群
