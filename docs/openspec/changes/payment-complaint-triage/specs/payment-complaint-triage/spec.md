# payment-complaint-triage Specification (Delta)

## ADDED Requirements

### Requirement: 投诉取证跨系统且只读

系统 SHALL 仅通过支付系统提供的**只读**接口获取订单、支付流水、回调与退款记录，SHALL NOT 执行任何写操作或资金动作。

#### Scenario: 取证不触发资金操作

- **WHEN** 对任一投诉执行取证
- **THEN** 只发生读请求；代码中不存在退款、补单、冲正等写方法

#### Scenario: 数据源不可用时显式降级

- **WHEN** 支付侧接口超时或返回错误
- **THEN** 报告输出"证据不足：支付侧不可用"，不得给出资金去向结论

### Requirement: 判定使用业务规则表

系统 SHALL 依据显式规则表判定情形（重复扣款 / 已扣款未到账 / 支付超时 / 退款失败 / 订单状态卡滞 / 与机器人答错相关），SHALL NOT 复用技术根因枚举。

#### Scenario: 重复扣款

- **WHEN** 同一订单存在两笔成功支付流水且仅一笔被订单引用
- **THEN** 判定为"重复扣款"，并列出两笔流水的单号与时间

#### Scenario: 规则未命中

- **WHEN** 证据齐全但无任何规则命中
- **THEN** 输出"未判定"并列出已核对的规则，不得猜测原因

### Requirement: 处置建议不含执行

系统 SHALL 只输出处置建议文本（补单 / 发起退款 / 联系渠道 / 人工核对），由人执行。

#### Scenario: 建议可复制不可执行

- **WHEN** 报告给出"建议发起退款"
- **THEN** 输出为文本说明与所需参数，不调用任何退款接口
