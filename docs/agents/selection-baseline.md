# 选型对齐基线

> **唯一归属**：本文件定义"**做技术选型时以谁为基线、对齐什么、有意偏离什么**"。
> 与 `docs/agents/reference-projects.md` 的分工：那份列**本地有哪些参考仓库**（按域分组、何时查阅）；本份定**选型时的对齐纪律**与**当前对齐状态**。
> 与 `docs/agents/best-practices.md` 的分工：那份记**各能力域的「业界做法 ↔ 我们的现状」**（跨域）；本份管**「以谁为基线」**及**上下文治理与记忆域的逐维度对照**。同一事实只在一处维护。

## 原则

**技术选型 SHALL 优先对齐「生产在跑 + 领域契合」的实现；凡有意偏离基线，SHALL 写下偏离理由与代价。**

判据（不是"谁流行"，而是"谁在被真实运行"）——按权重排序：

1. **生产验证**（正在生产跑的优先）
2. **领域契合**（同领域/同形态优先，如 RAG + 多轮会话 + 自建会话历史）
3. **可迁移深度**（源码可读、机制完整、注释/ADR 记录了取舍的优先）

## 本域基线（上下文治理与记忆）

四家为本域对齐基线：**WeKnora**（Go，生产，压缩与长期记忆机制最完整）、**LangBot**（Python，生产在跑，架构决策记录最规范）、**deepseek-harness**（TS，会话事件溯源与压缩契约最严谨）、**CowAgent**（Python，长期记忆形态最完整）。

> 这四家的共同点：**都不用框架的会话状态持久化**（无 LangGraph checkpointer / Store）。此结论已落为 ADR-0018 的决策依据。

## 对齐状态表（上下文治理与记忆域）

> 「状态」三档：**✅ 对齐**（与基线一致或更严）/ **⚠️ 偏离**（有意或待修，须有理由）/ **❌ 未做**。

| 维度 | 基线做法（出处） | 我们的做法 | 状态 |
|---|---|---|---|
| 上下文预算口径 | **绝对量**：`阈值 = 窗口 − ReserveTokens`（WeKnora，理由："要装下的是响应，其大小不随窗口缩放"） | 绝对量 `HISTORY_TOKEN_BUDGET`（集中常量） | ✅ 对齐（比 deepseek 的"比例"更稳） |
| 触发判据 | token 预算，**明确不"保当前轮"**（WeKnora） | 与裁剪**同口径**算出的「被丢弃段」 | ✅ 对齐（更严：避免了"空转"） |
| 保留策略 | `KeepRecentTokens` + 预算（WeKnora）/ `max_rounds` + 条数 hard cap（LangBot）/ `retainRatio` + tool-pair 平衡（deepseek） | 轮数(10) + 绝对预算 双约束 | ✅ 对齐 |
| **摘要长度上限** | 8192（deepseek）/ `reserve×4/5 ≈ 13107`（WeKnora） | **2048** | ⚠️ **偏离**（小一个数量级；理由是要给保留尾部留空间，但预算本身也偏小）→ 待修 |
| **预算量级** | `窗口 − 16384`（约 11 万，WeKnora）/ `窗口 × 0.8`（deepseek） | **16384** | ⚠️ **偏离**（保守值定于"只能丢弃"时代）→ 待标定 |
| 摘要**是否持久化** | 不落库（WeKnora，明确"轮内可丢派生"）/ 追加进事件日志 + surface 影子化（deepseek）/ 落文件（CowAgent） | 落 Redis，跨轮复用 | ⚠️ **有意偏离**（与 CowAgent 同族；理由：WeKnora 的压缩只解"轮内窗口"，我们要解"跨轮语义"） |
| **「不增长」严格度** | 「must not be longer than the previous summary **unless genuinely new facts require it**」（WeKnora） | **严格不增长**（无例外） | ⚠️ **偏离（过严）**→ 待修 |
| **失败处置** | 重试 2 次（WeKnora，每次 60s）/ 3 次（CowAgent） | **不重试**（靠下一轮触阈自然重试） | ⚠️ **偏离**→ 待修 |
| **摘要边界表示** | `shadowedSeqs` + `shadowedRange` + `sourceEventSeqs`（deepseek） | `covered` = 消息条数 | ⚠️ **偏离（偏薄）**→ 待修 |
| 历史存储清理 | 条数 hard cap + retention 清理（LangBot/WeKnora/CowAgent 全有） | **仅 TTL** | ❌ **未做** |
| 短期记忆真源 | 普通表 / 文件 / 内存日志（四家一致，均非框架快照） | Redis `chat_history:{sid}` + PostgreSQL `conversation_history` | ✅ 对齐（ADR-0018） |
| 长期记忆底座 | 自建：PG 多表 + 类型化 + 双时态（WeKnora）/ 文件真源 + 派生索引（CowAgent） | 规划中 | ✅ 规划对齐（ADR-0018） |
| 并发守卫 | 四家未提（其压缩在轮内，无跨轮写） | 独立锁 + best-effort + 启动期残留清理 | ✅ **我们更严**（有意差异，理由：我们有跨轮异步写） |
| 降级可观测 | 记降级 + 回退（WeKnora `rawArchive` / deepseek 保留最新 durable surface） | `summary fallback` 带 reason + 回退纯裁剪 | ✅ 对齐 |

## 怎么用

- **设计新能力前**：先查本表——该维度是否有基线做法？若有，**默认对齐**。
- **偏离时**：SHALL 写下「偏离理由 + 接受的代价」，落在该变更的 `design.md`（若属不可逆决策则落 ADR）。
- **发现新基线**：若某项目在本域出现更强/更成熟的做法，SHALL 更新本表并评估是否改向（改动大则按 ADR 流程）。
- **本表不是"抄这个"**：基线是**判断依据**，不是实现范本——例如我们的"触发判据与裁剪同口径""聚合预算"两条比基线更严，应保留而非回退。

## 维护

- 本表随「上下文治理与记忆」域的变更同步更新（新增对齐项 / 状态变化 / 新增基线项目）。
- 状态为 ⚠️ / ❌ 的行 SHALL 指向一个已知的待办（变更、需求池条目或 ADR 的「不解决的问题」），不留悬空。
