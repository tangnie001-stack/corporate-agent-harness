# 调研文档

> 本目录存放**定稿的调研结论**：一次性或有时效性的**外部事实汇总**（业界做法、竞品与参考项目对照、第三方服务评估、实测对比）。
> 它回答"**外面是什么样**"，不回答"我们定了怎么做"——后者归 `docs/adr/`。

## 什么时候写调研文档

**写**：

- 需要**外部事实**才能推进的选型（业界主流怎么做、某库的真实行为、某服务的真实约束）
- **多候选对照**评估（候选清单、取舍、推荐结论与依据）
- **参考项目实读结论**（本地 `../github/` 镜像的实现对照，按域提炼可借鉴与不可借鉴）
- **实测 / 测量记录**（性能对比、token 开销、行为验证）

**不写**：

- 当前生效的**规则与契约**（怎么写代码、接口长什么样）→ `docs/agents/`
- **决策定论**（我们选 A 不选 B、代价是什么）→ `docs/adr/`
- 本次变更的**设计方案** → `docs/superpowers/specs/`
- 本次变更的**执行编排**（proposal / design / specs / tasks）→ `docs/openspec/changes/`
- **实施步骤** → `docs/superpowers/plans/`
- 未定稿的**草稿与中途产物** → `docs/tmp/`

## 与既有文档的分工

```
docs/research/     外面是什么、候选怎么比、依据是什么   ← 本目录（论据）
      │ 喂
      ├─▶ docs/adr/                    我们定了什么、为什么、代价、何时复查（承诺）
      └─▶ docs/superpowers/specs/      这次变更怎么设计
              └─▶ docs/openspec/changes/   这次变更怎么执行
```

| 目录 | 回答什么 | 生命周期 | 粒度 |
|---|---|---|---|
| `docs/research/` | **外部事实是什么** | ⚠️ **冻结记录**，不随代码回写 | 一个调研主题 |
| `docs/adr/` | **为什么当初这么定** | ✅ 不可变，只追加（取代靠反向指针） | 一条决策 |
| `docs/superpowers/specs/` | **这次变更怎么设计** | 可随设计演进修改 | 一次变更 |
| `docs/openspec/changes/` | **这次变更怎么执行** | 实施完成后归档 | 一次变更 |
| `docs/agents/` | **当前生效的规则与契约** | 持续维护，只描述现状 | 一条规则 |

**关系**：一份调研文档可以喂出 **0~N 条 ADR** 与**一次**变更的 spec。调研文档本身不承担"决定"的责任，只承担"事实与依据"的责任——**调研的结论绝大多数不是决策**，硬塞进 ADR 会让 ADR 退化为现状文档，那是 `docs/agents/` 的职责。

**为什么缺了它会出问题**：`docs/adr/0020` 的背景一节自述，2026-07-28 引入又关掉 LiteLLM 网关这件事"仓库里找不到原因，既无 ADR，也无 change/plan 记录"——事实没落档，决策就只能事后靠回忆追记，可信度打折。调研文档就是防这个。

## 命名与格式

```
docs/research/YYYY-MM-DD-<kebab-case-主题>.md
```

- `YYYY-MM-DD`：**成文日期**（调研是时点性的，要能被排序与判断新鲜度）
- 主题：**英文** kebab-case（便于检索与跨工具引用）
- 正文用**中文**（与项目文档一致）
- 建议结构：结论摘要 → 详述 → 反面与风险 → 待确认项 → 来源

## 两条硬规则

1. **调研产物是冻结记录，不随代码回写数字。** 报告里的测量值、token 数、候选评分是"那次调研的记录"。结论后来被推翻时**不删原文**，改为在头部标注「后续修正见 xxx」，或另写一篇并在头部标注取代关系；重跑测量请另存，勿原地改数字。
2. **来源必须可核。** 引用外部事实附 URL；引用本地代码附 `文件路径:行号`。**实读源码得出的结论优先于 README 转述**——同名目录可能名不副实（例：`financial_rag-main/mcp_server/` 自称 FastMCP，实为手写 REST，并非 MCP 协议）。

## 与 `docs/tmp/` 的边界

`docs/tmp/` 是**草稿区**（`deep-research-*.md`、中途 brief、临时清单），可以随时丢；本目录是**定稿区**，写完即视为该主题的事实基线。定稿后应从 `tmp/` 清理，或把 `tmp/` 里的版本标注为草稿并指向本目录。

### 日期口径（为什么历史调研的文件名不带日期）

新调研命名 `YYYY-MM-DD-<主题>.md`，但**历史调研不补日期前缀**。三个候选来源的实测结论：

| 来源 | 判定 | 依据 |
|---|---|---|
| 文件系统 birth time | ❌ **不可用** | 6/7 份同为 `2026-09-25 02:45` —— 那是仓库从 `/mnt/d`（9p）迁到 ext4 时的**拷贝时间**，被迁移动作覆盖（ext4 的 crtime 在复制时重置） |
| git 首提日 | ✅ 可核 | 未被迁移污染（git 内容寻址，历史随 `.git` 完整搬运），有 commit hash 佐证；但语义是「**首次提交日**」，非「成文日」 |
| 文档自述日期 | ⚠️ 混杂 | 正文里的日期混着**被引用资料的日期**（如 `2025-04-03`、外部库版本/基准数据），无法自动区分「成文日」与「外部数据日」 |

**故日期写在「首次提交」列，不写进文件名** —— 冻结记录的第一原则是不写语义不准的数字；文件名保持稳定还能让任何漏改的旧引用被人肉对应。

**自本目录建立起，新调研一律落 `docs/research/`**，并在 ADR 里引用（`R2` 会拦截指向草稿区的引用）。
