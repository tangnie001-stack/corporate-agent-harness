# ADR-0025：模型长时不可用不做进程内自愈（快速失败 + 明确告知 + 人工部署级切换）

- **Status**：Accepted
- **Date**：2026-10-16
- **Deciders**：用户（拍板：降级产物 = **检索原文 + 明确告知**；确认「分钟级可人工介入部署级切换」成立，故不自愈）；助手（系统排查、实测取证与实现）
- **关系**：落实 change `timeout-and-degradation-hardening` 的 design **D9**（长时不可用的处置）与 D5/D6（重试分类与降级矩阵）；是 **ADR-0020**「不引入模型网关 / 放弃跨 Provider fallback」在**长时不可用尺度**上的直接应用与显式化；遵守 **ADR-0021** 的层边界（provider 兼容层**不是**网关、不做 fallback）；不取代任何在先 ADR。

## 背景与问题

生产链路的模型调用此前**超时零配置**（吃 SDK 默认：read 600s 平铺 + SDK 重试 2 次），且只有精排一处降级。上游**可用性类错误**（额度耗尽 / 鉴权失败 / 429 或 5xx 重试穷尽）在**长时尺度（小时~天）**下的处置**从未定义**：

- 抖动（秒~分钟）与长时不可用，被当成同一件事讨论 ⇒ 结论互相矛盾；
- 若主模型持续不可用，用户拿到的**产物**是什么？恢复靠谁、多久？

一个必须同时回答的**事实**：本仓**没有出站告警触发源**（无 metrics 端点；`src/api/alerts.py` 是**入站**接收阿里云告警），因此"人工介入"在纸面上成立、**实际可能没人被叫醒**（该缺口已登记需求池 `H-12`）。

## 决策

1. **不引入进程内模型 fallback**（跨 provider 或换档），**抖动与长时不可用分别处置**：
   - **抖动（秒~分钟）**：由**有界重试**处置（仅可重试类：超时 / 连接 / 429 / 5xx；输入校验类与 401/403 **不重试**）；
   - **长时不可用（小时~天）**：**快速失败 + 明确告知 + 人工部署级切换**，**不做自愈**。
2. **降级产物不是"什么都没有"**：LLM 不可用时，**本轮已取得检索结果** ⇒ 返回**已检索原文 + 明确告知**；**无检索结果** ⇒ **仅明确告知**。⇒ 保住溯源、零编造。
3. **恢复手段 = 部署级切换**（改 `.env` 的 `LLM_PROVIDER` + `--force-recreate`，约 2 分钟），**不是**进程内自动切换。
4. `embedding` / `rerank` **没有备选绑定**（注册表里只有 dashscope 提供这两个角色）⇒ 其长时不可用**只能语义降级**（退词法路 / 跳过精排），不涉及模型切换。

## 理由

1. **fallback 的可用窗口比直觉窄**：主链路是**流式**的，而「流已开始输出即不得重试/换模型」（否则重复输出给用户）⇒ fallback 只能在**首 token 之前**触发；而首 token 前的失败多为连接/限流类，**重试即可解**。"模型整体不可用"时换模型多半同样不可用。
2. **换更弱的模型兜同一套 prompt，风险是"看起来正常但更差"**：已踩过换模型致契约变化（`temperature`/`top_p` 被 400、思考档位失效）。对有溯源要求的产品，**静默降质比明确告知失败更危险**。
3. **ADR-0020 拒绝网关的三条理由在此同样成立、而收益更小**：链路耗时上升 / 只覆盖部分角色 / 内存开销；而进程内 fallback 的收益（省掉分钟级窗口）小于它的代价。
4. **层的边界**：ADR-0021 明写 provider 兼容层不做 fallback ⇒ 任何 fallback 都必须落在该层**之上**，那会引入一个新的"策略层"概念（本变更的 design D1 明确不抽新层）。

## 被否的替代方案（记录以免日后重开）

- **(B) 进程内自动换 provider**：机制成本低（两个 provider 早已配置好），但 ① 不能落在 provider 层（ADR-0021）；② 与 ADR-0020 有**精神张力**；③ **质量差异无法自动判定** ⇒ 金融域"静默降质"不可接受。
- **(C) (B) 的收敛版**：只在「**可用性类错误 + 首 token 之前**」触发，并**把"当前在用备选模型"透出**（事件 + 可见标记），避免静默降质。**本次不启用**；**若将来 SLO 要求缩短不可用窗口，优先按 (C) 形态实现**（届时须新增 ADR 并在本 ADR 的 Status 加反向指针）。

## 后果与代价（明确接受）

- **代价（主要）**：**主模型长时不可用 = 本服务对"自然语言答案"不可用**，窗口 = **人响应时间**。用户已确认该窗口可接受（分钟级），替代方案（换模型续答）的风险更高。
- **代价（隐藏但已知）**：**"分钟级可介入"的前提是有人被叫醒**，而出站告警触发源**今天不存在** ⇒ **该前提未成立**。本决策**不**把告警系统建进来（那是运维接入，归 `H-12`：阿里云 Grafana + 阿里云日志 SLS，最小出站源 = `error_*.log` 接 SLS 告警）；本变更只保证**失败以结构化事件留痕**（字段与取值可被判据匹配），使边缘侧**配得出规则**。
- **连带**：长时不可用时"用户拿到检索原文"，意味着该轮**不落"空内容 + complete"**（本变更已覆盖）；**首次模型调用即失败**时**并不存在**检索原文 ⇒ 只告知，不得承诺返回它。

## 前提与边界

- 本 ADR 只定义**进程内**的行为；**部署级**切换（改 `LLM_PROVIDER`）是本项目的**既有能力**，不在此约束内。
- 评测链（`RAGAS_*` 族、含 `judge`）**不适用**本 ADR：其重试/超时口径归评测链自身（见 ADR-0024 及其后续取代者）。
- 观测事件的字段口径以 `src/core/log_event_specs.py` 的 `EVENT_SPECS` 为**唯一归属**。
