# ADR-0022：RAGAS 出题的输入边界由使用方负责；评估检索与出题同范围

- **Status**：Accepted
- **Date**：2026-10-13
- **Deciders**：用户（决策：白名单保留，评估检索须搭配同一白名单）；Claude（调研与综合）
- **关系**：为 RAGAS 评测链路（`evaluation-pipeline`）的输入口径决策，不取代任何在先 ADR。证据主体见 `docs/research/2026-10-13-ragas-testset-generation.md`。

## 背景与问题

2026-10-13 对生成的测试集做冒烟评测（`testset_4a1dcb8bb340473c8149ead5b7f75873_v1/v2/v3`）时，暴露出**两条独立的问题**，都指向"出题输入边界"这件事：

**① 题面不自足 → 被测 Agent 走澄清 → 单轮评测接不住。**

知识库里是**三家公司的财报**，而白名单圈定的是其中两家（东软 + 腾讯）。生成的题却是「稀释每股收益本报告期多少，比上年同期变动幅度多少？」这类**不点公司名**的问题。实测 5 条中第 1、3 条触发了 `ask_user` 澄清；评测是单轮、无用户应答，Agent 澄清超时后把全部候选数据倒出来（答案 1850 字 / 上下文 32K 字符），导致 `answer_correctness` 均值掉到 0.36、`faithfulness` 掉到 0.67，且 5 个指标作业因超时变成 NaN。

**② 出题与评估的文档范围不一致（口径分叉）。**

| 环节 | 实际范围 | 证据 |
|---|---|---|
| 出题 | 只读**白名单的 2 份**（逐 `doc_id` 取分块） | `src/cli/eval_ragas_generate.py:268-270` |
| 评估 | 检索**整个 KB 的 4 份**，完全不看白名单 | `src/cli/eval_ragas.py:737`（`get_all_chunks(kb_id)`） |

⇒ 题从 2 份出，检索在 4 份里找。**这不是校验能拦住的错误**，只能靠口径对齐。

**关键调研结论（决定了"责任在谁"）**：

- **RAGAS 对出题输入几乎不提要求**。官方 getting-started 只说"用你自己的文档"，**没有任何输入文档的要求或最佳实践章节**；源码里的硬校验**只针对 LLM / embedding 客户端是否提供**（`ragas/testset/synthesizers/generate.py:176,182`），唯一与文档有关的硬约束是"KG 里必须有节点带 `summary_embedding`"（`ragas/testset/persona.py:94`）。文档类型、数量下限、单主题性、是否同一家公司——**一概不管**。
- **RAGAS 不做"问题级"质量校验**。当前 0.4.3（也是 PyPI 最新）整个 `testset/` 包对 `self-contained` / `ambiguity` / `independence` / `QuestionFilter` **零命中**；出题 prompt（`ragas/testset/synthesizers/single_hop/prompts.py:23-35`）只要求"答案忠于上下文"，**不提问题是否自足/无歧义**。旧版曾有 `QuestionFilter`（判据即 Independence + Clear Intent，不合格则重写），随 PR #1401（`feat!: moving experimental.testset to replace old testset`，2024-10-02 合并，＋101 / −6785 行）**整体替换时被删**，且**官方无任何说明**（release notes / CHANGELOG / 文档均无）。
- **官方设计反而期望多源语料**（multi-hop 需 "two or more sources"、abstract "across different sources"），所以"一个库里多家公司"对它不是异常输入。

⇒ 因此**"选哪些文档参与出题"与"生成的问题该不该自足"这两件事，官方都不提供机制、也不承担结果——它们是使用方的职责。**

**附带实测发现（本次一并记明）**：官方 `default_transforms` 共 7 个（`ragas/testset/transforms/default.py:185-207`），我们只跑了 5 个（`src/cli/eval_ragas_generate.py:386-395`），**缺 `ThemesExtractor` 与 `CosineSimilarityBuilder`**；导致 `MultiHopAbstractQuerySynthesizer` 取不到聚类而被**静默丢弃**（`logs/app_2026-10-13.log:3871`：`Skipping multi_hop_abstract_query_synthesizer ... Cannot form clusters.`；v1 实测 20 条的出题器分布只有 `single_hop_specific` + `multi_hop_specific`）。

## 候选方案

| 方案 | 做法 | 代价 | 收益 |
|---|---|---|---|
| A | **取消白名单**，整个 KB 出题 | 扫描件/不相关文档进入出题；跨公司指代更不可控；无法按需缩小范围 | 口径天然一致（出题=评估=整库）；少一处配置 |
| B | **保留白名单，评估检索仍整库**（= 现状） | 出题范围 ⊂ 评估范围，两个口径无声明地分叉 | 无 |
| C | **保留白名单，且评估检索按同一白名单限定** | 评估不再代表"整库问答"的质量，只代表"白名单范围内"的质量（这正是我们要量的） | 口径一致且可解释；出题输入可控；为后续"按公司出题"留出维度 |

## 决策

**选 C：保留文档白名单（`RAGAS_DOC_WHITELIST`）作为出题的输入边界，并让评估侧检索使用同一白名单，两端同范围。**

同时明确**不做**的一件事：**不自造"问题级质量过滤器"**。既不复活 RAGAS 已被删除的 `QuestionFilter`（那是对已移除内部实现打补丁），也不在此 ADR 中引入新的问题校验机制——题面自足性是否要治、怎么治，属另一条决策（见「不解决的问题」）。

## 理由

**最关键的一行**：RAGAS 官方既不提供"文档选择"，也不提供"问题自足性校验"——这两件事**没有官方机制可依赖**，所以**必须由我们显式承担**；而"承担"的最小形态就是**一条受控的输入边界 + 两端口径一致**。

- **为什么不在 A（取消白名单）**：把整库喂进去会把"是否该出题"的判断交给运气（扫描件、不相关件、跨公司指代都无法排除）。RAGAS 不做过滤，我们取消白名单等于**放弃唯一的输入控制点**。
- **为什么必须修 B 的分叉**：出题范围与评估范围不一致时，指标既不能解释成"整库质量"也不能解释成"白名单质量"——**两个都不是**，报告读出来的数字没有归属。
- **为什么白名单合规（尽管它硬编码了 doc_id）**：白名单承载的是"业务上哪些文档该进评测语料"这一**使用方职责**，官方不给替代机制；其实现问题（硬编码位置、绑 UUID 的脆弱性）是**实现层的债**，不构成本决策的错误。

## 后果

**正面**：

- 出题与评估**同范围**，指标含义可解释（"白名单语料范围内的 RAG 质量"）；
- 保住了输入控制点，为将来"按公司/按文档粒度出题"留下维度；
- 把"RAGAS 不管文档选择、不管问题自足"这一**反直觉事实**落档，避免后人反复重新争论（例如再次提出"为什么不让 RAGAS 自己过滤"）。

**负面 / 接受的代价**：

- 评估指标**不再代表全库问答质量**——知识库里的其他文档不参与评测；这是刻意的取舍（我们要量的是受控语料上的质量）。
- 白名单**绑 `doc_id`**（`src/config/settings.py:174-177` 硬编码 UUID）：同一份文件**重新上传会得到新 `doc_id`**，白名单会**静默失效**（题出少甚至出空，但不报错）。列为已知债，见「复查触发条件」。
- 白名单值仍写在源码 `settings.py` 里（环境相关值放源码，违反了本仓"环境值走 `.env`"的惯例），本次**不改**，同列为债。

**不解决的问题**（明确列出，避免后人误以为这条 ADR 管了它）：

1. **题面自足性**：题面仍可能不点公司名（RAGAS 出题 prompt 不管），被测 Agent 仍会走澄清而单轮评测接不住。本 ADR 不治它——治它的候选手段（`llm_context` 软引导 / 单公司语料 / 多轮评测）另行决策。
2. **出题器只跑通两路**：缺 `ThemesExtractor` 与 `CosineSimilarityBuilder` 导致 `MultiHopAbstractQuerySynthesizer` 被静默丢弃（实测见「背景」）。修不修、怎么修（补齐 `default_transforms` 全量）另行决策。
3. **白名单的实现债**：硬编码位置与 `doc_id` 脆弱性，本 ADR 只登记不修。

## 复查触发条件

1. **白名单静默失效**：同一文档重传后题量异常下降/为空时。
2. **RAGAS 上游变化**：若新版 RAGAS 重新引入问题级质量校验（或提供官方的文档选择/过滤机制），则应重估"由使用方承担"这一前提。
3. **多轮评测落地**：若把"澄清能力"改为被评能力（多轮 + 用户模拟器），则"题面必须自足"这一约束的紧迫性下降，本 ADR 的边界可能需要重划。
4. **白名单值外置**：若出现第二套评测语料（多个 KB / 多组文档），则必须把白名单从 `settings.py` 迁到 `.env` 或 CLI 参数，届时重审本条。
