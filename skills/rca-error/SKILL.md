# 值班诊断（trace 维度）

## 何时用

- 用户给出 `trace_<uuid>` 形态的标识，问某次请求为什么失败、为什么答错、慢在哪。
- 用户描述"某个会话答错了""这个报错查一下"并能提供 trace_id。

**不适用**：用户只给接口名/时间范围（改用日志工具）；支付投诉（不在本域数据内）。

## 怎么做

1. 先确认分型再调用：`kind=5xx`（服务端报错）、`kind=4xx`（客户端侧）、`kind=answer`（答错，默认）。判断不了就用 `answer`。
2. 调用 `diagnose_trace(trace_id, kind)`，只调一次。
3. 把返回的卡片**原样**转述：档位、归属、根因、依据、详情链接。卡片里的数字不重算、不改写、不补充。
4. 卡片说"未判定"就回答未判定，并说明缺哪类证据；不得自行推断根因。
5. 工具返回的是提示文案（格式错 / 未找到 / 不可用）时，直接把该文案给用户，不要重试或换 id 猜测。

## 禁止

- 不得执行任何修复动作（重放、重入库、改配置），只能给建议。
- 不得把证据原文贴进群聊；详情页需登录查看。
- 不得因为"查不到"就说服务正常。
